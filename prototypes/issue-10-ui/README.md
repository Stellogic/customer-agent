# PROTOTYPE — 首个纵向切片页面信息架构

> Throwaway UI prototype：只用于回答 Issue“确定首个纵向切片的页面信息架构与关键交互”。
> 它不是 React 生产实现，不连接 Spring Boot、LangGraph 或真实 SSE。

第一轮三方案原型保留在提交 `a32388f`。根据用户评审，当前版本收敛为两个真正独立的产品入口：

- 客户帮助中心：自助内容、我的工单和帮助中心式会话窗；只呈现公开沟通与公开状态。
- 内部工作台：客服与审批人共用后台应用骨架，但登录后菜单、路由和数据由权限决定。

底部的角色/状态切换器明确标记为 `THROWAWAY PROTOTYPE`，只用于评审，不属于产品导航。

## 一条命令运行

在仓库根目录执行：

```powershell
python -m http.server 4173 --directory prototypes/issue-10-ui
```

然后打开：

```text
http://127.0.0.1:4173/?surface=customer
```

## 评审方式

1. 用底部原型工具切换“客户帮助中心 / 审批人工作台 / 客服队列”，确认三者不是同一产品页面。
2. 用场景按钮检查客户澄清、等待审批、`UNKNOWN` 自动对账、拒绝转人工和最终结果。
3. 点击“模拟断线”，确认页面停止增量更新并通过“重新同步权威状态”收敛。
4. 在审批视图领取提案，检查 15 分钟租约、批准、拒绝原因必填和审批结束后访问终止。
5. 确认内部菜单和数据随 `APPROVER` / `SUPPORT` 权限变化，产品界面不存在自由切换身份的入口。

所有数据均为合成数据。客户视图不展示调查事实、工具 payload、提案草稿、审批细节或内部 Agent 流；客服失败路径只展示共享队列最小摘要。
