# Spring 最小必要核对：职责对齐记录

本文记录用户通过 grill-with-docs 逐轮确认的决定。尚未确定的分支不作为已批准的实施要求。

## 已确认：Spring 的职责边界

用户确认：Spring 只做最少且必要的核对，例如业务事实等有明确正误的内容；其他内容不由 Spring 拦截，可以交给人工审批。

Spring 保留对权威业务事实、工单及证据范围、权限、金额、审批与执行状态、有效处理代次等明确规则的核对。措辞、同义表达、语序、标点及表达质量不作为 Spring 拒绝回复的理由。不以不断增加允许词汇表的方式实现这一边界。

## 已确认：普通回复直接发送

用户接受推荐方案A：普通回复通过必要核对后直接发送，不新增逐条正文审批流程。补偿审批、客户要求人工或调查无法继续时，沿用人工审批／接管路径。

## 已确认：确定输出与自由正文分开

用户进一步限定：如“已退款”等文字，只有明确要求模型唯一输出该确定内容时才可以拦截；其他自由表达不拦截。

实施边界理解为：对协议规定的确定值、枚举和结构化业务字段保留验证；自由回复正文不再依赖关键词、正则、指定措辞或语义判断作拒绝依据。正文中的“已退款”等文字不作为执行退款或更改权威业务状态的依据。Agent侧同步移除对应正文语义拦截，避免只是把拦截从Spring移到Agent。

这一取舍允许自由正文存在错误陈述而不被自动语义拦截；结构化事实校验不等于全文事实保证。保留补偿及退款的真实执行权限、审批和状态约束。用户已整体确认上述实施理解，长期决定见[ADR 0011](../adr/0011-structured-authority-and-free-reply-text.md)。
