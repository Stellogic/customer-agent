# Issue #153 交付验证

## 交付范围

- 同一客户、同一订单的一次自然语言受理可形成多个受控问题候选。
- 低置信候选先澄清，已确认候选在澄清轮次中保持不变。
- 多个待澄清类型按稳定顺序持久化并逐项处理；包裹、物流和重复扣款的否定答复均会显式移除队首类型，不会进入拟建工单集。
- Spring 校验跨轮状态转换：既有问题不可丢弃或改写，每轮至多确认或否定待澄清队首，其余队列必须保持。
- Agent 合并问题时保持既有顺序，并把本轮确认的待澄清队首追加到末尾，避免合法澄清被 Spring 权威校验拒绝。
- 客户一次确认后，在同一数据库事务内创建全部工单及不可变共享受理记录；任一步失败时整体回滚。
- 确认请求使用稳定请求身份；同键重放返回原共享记录与原工单集合，不重复创建。
- React 客户界面呈现多问题确认、原子创建说明、成功工单列表、空态、加载态和失败态。

## 权威边界

- LangGraph 只返回受控问题类型和候选订单；Spring 重新校验候选、订单版本和确认语义。
- Spring 持有事务、幂等、正式工单创建和共享记录写入权威。
- 共享受理记录表只向应用授予 `SELECT`、`INSERT`，不授予更新或删除能力；问题关联只保存受控类型与稳定工单引用，不复制问题正文。
- 本票没有调用真实模型，固定假模型仅用于确定性测试，真实模型费用为 0 元。

## 验证结果

- `pwsh ./scripts/check.ps1`：通过。
- Agent：格式、静态检查、类型检查与 209 项测试通过。
- Backend：格式、Checkstyle、构建与 146 项测试通过。
- Frontend：格式、Lint、类型检查、构建与 90 项测试通过，3 项按既有条件跳过。
- 全栈 smoke：Flyway V1-V24、Spring、PostgreSQL、LangGraph、补偿执行器与 React 集成通过。
- 真实浏览器：28 项主验收通过；会话重启/到期验收通过（按既有条件各轮跳过 1 项）。
- Issue #153 窄屏真实链路：低置信澄清、两个候选、一次确认、两个不同工单、共享记录、同键重放均通过，无横向溢出。
- Issue #153 桌面失败链路：确认失败时不展示部分创建结果，并明确提示不会创建部分或重复工单。
- 隔离数据库聚合回读：共享受理记录 `1`、共享问题关联 `2`、不同工单引用 `2`、存在的正式工单 `2`。
- 隔离 live API 冲突回读：相同幂等键配合不同正文返回 HTTP `409`，响应保留原共享记录 ID 与原 `2` 个工单的权威快照；确认后待澄清记录为 `0`，共享问题关联表不存在问题正文复制列。
