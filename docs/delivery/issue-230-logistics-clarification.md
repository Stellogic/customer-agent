# 核心验收的一次物流澄清

领域契约允许低置信度问题先澄清，再统一确认。核心物流验收此前直接等待确认标题，并要求恰好一次受理调用，把进入合法澄清分支的结果也记为失败。

核心物流场景现在允许一次明确的物流澄清：通过正式页面回答“确实延迟，请核实物流状态。”，随后必须进入统一确认。再次追问、订单改变、额外订单、非物流问题或提前建单仍失败。既有共用辅助函数默认行为保持原样，仅核心矩阵显式启用。

持久调用记录只允许 START，或 START 后恰好一次 FOLLOWUP；NEXT_ORDER、RESTORE 或其他额外调用仍失败。供应商尝试、token 和费用仍由真实审计计量，不用固定一次受理代替。

离线无补偿样本1保持直接确认，样本2由内部供应商夹具确定性返回物流 UNCERTAIN，以覆盖澄清分支。夹具仍故意将额外输入候选排队，保留显式订单范围的回归能力。

此前真实运行的失败和未运行分母保持原样。该验收调整不改写旧结果，也不代表真实矩阵已经通过。按用户要求，完成离线验证后停止，不自动重跑真实模型。#230保持未完成，#174继续暂停。
