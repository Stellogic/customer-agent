# #229 支付事实与人工核查交付

## 范围与基线

复用已交付的 #228（PR #232），正式基线为 `origin/main@dc878de2fd64e440e6ece9f96495179b6b8965c9`。独立工作树在 #228 门禁期间只准备测试；确认受测树与合入树完全相同后对齐 main，随后进行红绿实现。共享工作树及 #174 暂停状态保持。

重复扣款的必需事实仍由 Spring 场景策略发布，读取订单、支付退款、补偿待办三个能力。现有工具只提供物流政策，没有可用于重复扣款核查的支付政策，不能机械调用它来虚构依据。既有 REFUND_STATUS 场景保留原策略，物流约束保持。

支付结论省略延迟字段，主引用来自实际订单和支付记录；程序保留统一必需证据构造，模型仍可补查并生成自然说明。支付不调用物流补偿判断或影子判断，也不制造相应调用及费用。公开回复完整校验后由 Spring 发布，并复用既有事务进入人工核查，不新增资金动作或自动解决权限。
