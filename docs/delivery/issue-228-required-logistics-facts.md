# #228 物流必需事实与证据职责交付

## 基线与范围

继承已合入的 #226（PR #231），从 `origin/main@17e9a98ae2aeaedbc2bc9b6bebac521cc6b202ec` 建立独立工作树。实现 #227 的首个物流切片，保留共享工作树、旧 PR #214、#174 历史及暂停状态。职责决定见 ADR 0010，旧 ADR 0006 不改写。

Spring 的 `EvidenceSufficiencyPolicy.LOGISTICS_DELAY_REQUIRED` 是物流必需规则的唯一业务来源。既有授权能力目录增量返回 `requiredFacts`，包括策略版本、场景、事实类型、能力、结果字段、实际证据槽位及适用类别。其他场景返回 null，继续消费旧路径；重复扣款迁移由 #229 承接。

程序先确认订单，再依据目录读取尚未取得的必需能力，策略随 LangGraph 断点保存。五项能力包括订单、物流、支付退款、补偿待办和适用政策；不把订单规则列为必读。证据关系只绑定实际能力返回的当前代次引用。Spring 原有权限、代次、事实漂移、冲突、资格与审批检查保持。

模型在必读完成后决定是否补查、提交或转人工，并继续承担知识查询语义和自然回复。保留现有订单歧义澄清及恢复，不新增任意调查追问协议。DeepSeek 使用 prompt `investigation-action-v7` / schema `investigation-action-v4`；v5/v6 仍是旧历史候选。程序动作消耗动作数与时间，不制造模型调用、供应商尝试或费用记录；补充模型调用照常计量。
