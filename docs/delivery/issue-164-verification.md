# Issue #164 交付验证

## 交付范围

- 当前负责客服才能读取本工单允许的标准补偿方案；方案类型、资格、金额、上限和政策版本由 Spring 计算。
- 客服只能选择方案和受控理由提交审批，不能覆盖金额或方式；超出标准方案走独立例外补偿申请。
- 提交后形成不可变提案版本，遵守幂等和参与者继承；客户只看到安全的类型、金额和「待审批」。
- 客服补偿面板与客户待审批投影覆盖 loading、empty、error、提交结果未知，以及桌面/窄屏信息层级。
- 不包含同订单多工单额度仲裁（#165）或自动解决（#162）。

## 关键顺序

1. 客服领取 HUMAN 工单后，Spring 按延迟政策重算当前方案；Agent 与客服请求都不能携带金额覆盖。
2. 选择方案与受控理由后写入新的 `compensation_proposal_revision`，并投影客户公开事件 `COMPENSATION_REVIEW_PENDING`。
3. 例外申请写入独立表，不插入普通提案修订。
4. 浏览器只消费 Spring 快照和 SSE；提交结果未知时按稳定请求身份查询权威结果。

## 验证矩阵

- Backend：负责客服读取方案、金额覆盖拒绝、幂等提交、例外接口隔离、客户投影字段白名单、模式变化/额度不足/事实失效冲突码。
- Frontend：标准方案列表、提交审批、empty/error/unknown、例外申请、客户待审批卡片、登出清除未确认提交。
- Chromium：`ORDER-DELAY-E2E-NORMAL` 领取后提交部分退款 26.80 CNY；客户看到类型、金额和待审批；窄屏信息层级单列。

## 最终门禁

- `pwsh ./scripts/check.ps1 -Issue 164`：待正式交付阶段仅运行一次并回填结果。
