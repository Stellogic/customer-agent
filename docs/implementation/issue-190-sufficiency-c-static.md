2026-08-31核对的官方证据：

- [人民币价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：Flash高峰输入未缓存3元/百万token、输出9元/百万token，公开上下文1M。本方案不预支缓存或低峰折扣。
- [官方Flash配置](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash/blob/fd53f94/config.json)：`max_position_embeddings=1048576`；[Responses兼容性说明](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)说明超过上下文报错。以完整上下文作为输入的保守上界，另加256输出，刻意不扣除两者共享上下文可能带来的节省。
- [Responses参数](https://api-docs.deepseek.com/api/create-response/)的 `max_output_tokens` 包括推理token；没有公开 `max_input_tokens` 或 `max_cost`。[token用量说明](https://api-docs.deepseek.com/zh-cn/quick_start/token_usage/)的字符换算是近似值，tokenizer示例未提供V4 Responses包装/schema的计费等价承诺。未下载或运行tokenizer，不把4096当硬上界。

每请求先预留 `1048576×3 + 256×9 = 3148032` 微元，即 **3.148032元**。账本以整数微元累计：

1. 串行请求前，若已结算上界＋未结算预留＋下一请求预留＞6000000，记 `BUDGET_INCOMPLETE` 并停止；预留先落盘，再发送。
2. 有合法usage的响应，按 `input_tokens×3 + output_tokens×9` 微元结算并释放差额；这仍是高峰无缓存支出上界，不是账单实付值。schema/质量失败与费用是否可结算分开。
3. 缺失/不可信usage、超时、网络/供应商失败时，保留未结算预留并停止。后续启动发现未结算项即报告协调，不清理、不重试，不猜“请求没到所以免费”。实返模型/fingerprint漂移也停止；合法usage仍如实记账。
4. 同一Git公共目录旁 `.local/issue190-sufficiency/cost-ledger.json` 是所有worktree/RunId共用账本。首次以既有#190无付费调用证据记录0元；已开始的开发阶段不因换RunId重跑。未结算费用不得人工清零来恢复预算；后续独立运行者必须承接同一账本及实返版本标识。
