## 失败后的静态分析与最小下一步

本节只阅读当前代码及既有报告，未重新执行模型、测试、评测，也未扫描替代参数。

1. **首轮运行错误属于实现缺陷，已修复。** 目录索引器的 JDBC 时间绑定使语料未入库；`quality-c` 已越过语料检查并执行全部查询，因此不能再用该错误解释本轮质量 FAIL。
2. **本轮最直接的问题是未经校准的拒答策略。** `KnowledgeRetrievalService.fuse` 在 RRF 之前检查最高余弦相似度；低于 `0.80` 就清空整个结果，包括可能存在的全文候选。余弦分数不是回答正确的概率，#189 只冻结了质量验收阈值，并未要求这个 `0.80` 业务判定。它是本实现预先选择、但缺少独立校准证据的策略，不能当作模型已证明不合格。原始报告中 36 条有答案查询均有向量候选，35 条最终为空；例如 `ans-logistics-01` 的第一向量候选就是相关的当前版本片段，相似度 `0.7869535684585571`，被该策略整体拒绝。此例不构成把阈值下调到某个数值的依据。
3. **全文方法在本轮未提供补充。** 全部 64 条报告的全文候选均为空。代码使用 `plainto_tsquery('simple', 整条问题)` 对现有 `search_vector` 匹配；连续中文与整句 AND 匹配缺乏适配，不等于 SQL 未运行。RRF 公式为两个合法候选列表的 `1/(60+rank)` 之和，排序方向及 Top-5 截断静态上没有发现算术错误；但本轮只有稠密一路有候选，不能据此宣称混合方法有效。中文词法替代方法仍留在 #168 边界内。
4. **没有证据把失败归因于硬过滤或评测算错。** 有答案请求全部 HTTP 200 且有向量候选；发布状态、当前版本、适用范围和索引代次先于排名过滤。编码使用冻结的查询指令、CLS/L2、512 维和 CPU，真实契约已通过。无答案 precision 为 `12/(12+35)`，与原始空结果计数一致。三个违规命中率为零，但大量整体拒答会掩盖排序后的风险，不能替代尚未完成的真实数据库与浏览器验收，也不能据此宣称权限验证已完备。

**建议的最小下一步需要一次范围明确的规格决策，而不是继续试阈值。** 先明确“候选检索成功”和“有足够证据可回答”的契约，以及是否允许为拒答策略建立与 `rag-eval-v1` 隔离的开发/校准数据。保持 #189 的题目、期望、质量阈值、固定模型全部不变；在独立数据上确定一个简单的拒答策略并冻结实现后，再由协调授予验证窗口，执行对应聚焦契约和一次冻结质量验证。单纯删除拒答或下调 `0.80` 可能牺牲无答案指标，当前没有证据证明能通过，不实施这类修改。若经独立校准后仍失败，再讨论 #168 的中文词法消融，不提前更换模型、引入 ONNX 或开放消费者。
