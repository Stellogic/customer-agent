## 唯一推荐：C-v2允许同一片段提供多条摘录

保留 `{"sufficient":boolean,"evidence":[{"chunk":integer,"quote":string}]}` 形状，**仅删除prompt和本地解析器中“chunk编号只能出现一次”的规则**。同一片段可以提供多条原文摘录；不新增跨条目唯一性规则，不静默去重、合并、截断或修复模型输出。仍最多5条，每条quote为1–24字符、非空白且必须是对应授权片段的原文；编号必须落在实际输入Top5内。精确字段/类型、true必须有证据、false必须空证据及既有错误即停行为不变。

理由是“一份来源能包含多个必要事实”，来源唯一并不是证据充分的必要条件。该修改消除一个与充分性无直接关系的跨条目限制；**不证明模型会稳定遵约或判断正确**。[最近失败](issue-190-c-remaining67-attempt-a.md)确为旧契约违规，不能重标为成功。新版本不解决原第5次未采集原文的未知失败。

须独立冻结 `C-v2` 的prompt/schema/config/解析契约与版本hash；即使schema字节可沿用，也独立标记其归属。这是经已见开发输出启发的**方法变化**，不能宣称与C-v1同一实验。BGE、RRF、授权/版本硬过滤、固定Top5、模型别名和其余充分性指令均不变；不切换接口或产品默认策略。

## 官方支持依据

DeepSeek [Responses 文档](https://api-docs.deepseek.com/api/create-response/)列出 `text.format=json_schema`；[兼容说明](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)称 `format` 完整支持。未查到 `strict`、`uniqueItems` 的专项承诺，不能据此断言不支持，也不能承诺它们保证语义。

[JSON Schema 官方说明](https://json-schema.org/understanding-json-schema/reference/array)的 `uniqueItems` 约束完整数组元素唯一，并非按 `chunk` 字段投影唯一。因此同一 chunk、不同 quote 的对象不是重复元素。

结构符合 JSON/schema 不证明引用真实或证据充分；这是结构与语义的区别，仍需应用检查及独立质量验证。本次仅查资料，未调用或验证服务。
