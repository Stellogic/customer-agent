## What to build

让客户侧 Agent 在解释一般规则和客服知识时使用已经通过最低中文质量门的混合检索，并在自然回复中提供安全的知识标题与更新时间。RAG 不得推断订单、支付或补偿事实。

## Acceptance criteria

- [ ] Agent 自主决定何时检索知识，检索请求仅携带当前工单所需的最小自然语言和适用范围。
- [ ] 检索结果携带知识条目标识、版本、适用范围和片段位置，并进入有依据自然回复校验。
- [ ] 客户只看到友好标题、更新时间和必要来源提示，不看到内部路径、chunk id、向量分数或不可见正文。
- [ ] 订单、物流、支付、补偿资格、金额和执行结果继续只来自 Spring 权威调查事实。
- [ ] 无答案、低于门槛、索引过期、Embedding 失败或适用范围不匹配时不生成无来源知识结论。
- [ ] 知识与当前权威业务事实冲突时业务事实优先，回复解释个案状态并记录知识冲突。
- [ ] 错误版本、越权条目和 prompt injection 内容不能进入回复或客户来源投影。
- [ ] 客户对话来源组件与原型视觉一致，覆盖桌面、窄屏、loading、无来源、冲突、error 和断线恢复。

## 开发与交付边界

流程清楚、交付可靠优先，并行效率其次。本票的原生 blocked_by 保留为集成与正式交付前置，不一概禁止隔离分支提前开发；仅在协调任务确认单一负责人、可提前范围及共享接口/文件归属后，推进下列独立部分。此说明本身不派发任务、不改变已有归属或窗口，也不要求同时启动所有待办票。

- 提前开发以最新 main 为基础；需要参考未合入前置时，记录其 PR/固定 SHA 和最小接口契约，只读对照，不改他人分支、不复制前置实现。接口尚不明确或多人将修改同一共享区域时，暂停该部分并由协调任务明确归属，其余独立部分可以继续。
- 允许编写测试源码和静态审查；所有实际测试、构建及重资源验证仍由协调任务安排并获取现有锁。锁为 FREE 或依赖已关闭都不代表自动放行。未运行的验证如实标注，可保存 Draft PR，不把局部静态审查当整票验收通过。
- 集成前同步已合入的前置及最新 main，核对接口、共享文件和迁移编号，完成必要的增量审查；按现有流程在串行交付窗口完成最终本地完整门禁、合入与关票。基线或内容变化不能沿用旧门禁证据。原验收范围和质量阈值不变。

### 本票可提前范围与必须等待的事项

- 可提前：客户来源 UI、安全投影、有依据回复的编排与测试源码；只使用已明确的知识结果、失败类型和权限范围契约。
