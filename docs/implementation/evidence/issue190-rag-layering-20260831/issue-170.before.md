## What to build

在 `HUMAN` 处理模式下，让当前负责客服请求工单总结、知识检索、政策查询和回复草稿。客服可以查看内部知识版本、标识与引用片段，但辅助输出必须人工审阅后发送，不能产生公开消息或业务副作用。

## Acceptance criteria

- [ ] 只有当前负责客服可以对其工单发起 Agent 辅助；领取撤销后立即失去请求和结果访问权。
- [ ] 辅助输入限于当前工单授权投影、近期公开消息、可重建摘要、调查事实和允许的知识范围。
- [ ] 总结、知识检索、政策查询和回复草稿使用明确的辅助类型与稳定请求身份。
- [ ] 客服可以查看知识标题、版本、内部标识、引用片段和适用范围，不显示模型思维链、prompt 或原始检索载荷。
- [ ] 回复草稿不会自动进入公开沟通；客服编辑并显式发送时仍经过人工回复权限与幂等校验。
- [ ] Agent 辅助不能切换处理模式、修改工单、形成或提交补偿、审批或执行任何动作。
- [ ] 无答案、知识冲突、索引失败或模型失败产生受控辅助失败，不影响人工继续处理。
- [ ] 客服详情中的 AI 摘要、建议、引用和 composer 复刻原型区域，并覆盖桌面、窄屏、loading、empty、error 和撤权清屏。

## 开发与交付边界

流程清楚、交付可靠优先，并行效率其次。本票的原生 blocked_by 保留为集成与正式交付前置，不一概禁止隔离分支提前开发；仅在协调任务确认单一负责人、可提前范围及共享接口/文件归属后，推进下列独立部分。此说明本身不派发任务、不改变已有归属或窗口，也不要求同时启动所有待办票。

- 提前开发以最新 main 为基础；需要参考未合入前置时，记录其 PR/固定 SHA 和最小接口契约，只读对照，不改他人分支、不复制前置实现。接口尚不明确或多人将修改同一共享区域时，暂停该部分并由协调任务明确归属，其余独立部分可以继续。
- 允许编写测试源码和静态审查；所有实际测试、构建及重资源验证仍由协调任务安排并获取现有锁。锁为 FREE 或依赖已关闭都不代表自动放行。未运行的验证如实标注，可保存 Draft PR，不把局部静态审查当整票验收通过。
- 集成前同步已合入的前置及最新 main，核对接口、共享文件和迁移编号，完成必要的增量审查；按现有流程在串行交付窗口完成最终本地完整门禁、合入与关票。基线或内容变化不能沿用旧门禁证据。原验收范围和质量阈值不变。
