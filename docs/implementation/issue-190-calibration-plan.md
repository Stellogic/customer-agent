## 最小修复决策

- [PostgreSQL 18 官方文档](https://www.postgresql.org/docs/18/textsearch-controls.html) 明确 `plainto_tsquery` 在词项间插入 AND。本轮在写入与查询两侧复用 [Lucene CJKAnalyzer 10.5.1](https://lucene.apache.org/core/10_5_1/analysis/common/org/apache/lucene/analysis/cjk/CJKAnalyzer.html) 的重叠双字词项、宽度与大小写归一化；查询以 OR 召回。仍用 PostgreSQL `tsvector` / `ts_rank_cd` 排名，不创建 Lucene 索引或新服务。Lucene 是 Apache-2.0 依赖，Java 25 满足其 Java 21 起的运行要求。
- 固定分析器版本，不维护项目中文词典/停用词或手写分词器；不用全文命中直接判定可回答。基础中文全文修复属于 #190；#168 保留独立消融与可选 ONNX 模块。
- 两路候选仍先硬过滤，分别取20条，RRF常数60、Top-5不变。把 `0.80` 常量替换为由独立数据生成的单一余弦门槛。RRF负责相对排序，校准后的最高合法稠密相似度负责决定是否返回合格结果；两个概念分别记录。
- [BGE 官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5) 建议根据具体数据的相似度分布选择门槛，不能把绝对余弦值解释为正确率。本轮不增加模型、不微调，不采用假回退。

## 数据来源与隔离

`agent/src/baseline_agent/knowledge_calibration_v1/data.json` 是本轮由 Codex 编写的合成开发数据，不来自外部真实用户，也不是独立第三方测试。使用图书借阅、温室养护、展馆寄存、泳道预约、露营器材、天文馆参观六个虚构主题，与冻结语料的物流、退款和审批主题分离。每个主题有标题及知识段落，包含可直接回答的改写问句和领域相关但正文没有依据的问句。先写明来源与划分，再运行模型。

前四个主题用于校准选择，后两个主题的查询仅作留出审计。全部文档作为固定候选语料，两组采用相同的标题/段落粒度及查询指令。每个有答案查询显式指定必要段落ID；无答案查询的期望列表为空。主题隔离比随机拆分同义句更严格，但样本小且全为合成，不能保证迁移到业务知识的效果。

校准器只加载独立开发数据和冻结编码器协议，不读取冻结查询、期望命中或历史逐题失败报告来选择门槛。旧 `issue190-quality-c.json` 保留原字节。运行报告记录数据/源码SHA-256、固定模型revision、环境、全部开发分数、留出结果和耗时；报告不能覆盖既有文件。

## 预先确定的选择方法

1. 用同一离线编码器生成全部独立文档与问题向量，按精确余弦计算最高候选分数，保留真实分数和必要段落排名。
2. 只在校准组分数的相邻中点及两个端点选择单一阈值；不手填候选数值，不使用冻结集分数。
3. 按“有答案接纳率与无答案拒绝率中较小者最大”选择；并列时取两者平均更高的，再并列取更高阈值。选择逻辑不读取留出标签。
4. 选择完成后只计算一次留出审计，分别报告接纳/拒绝情况与必要段落 Top-5 命中，不根据留出结果继续调阈值。未采集的结果明确留空。
5. 将实测报告连同选定门槛审阅、提交后才更新产品策略文件；没有有效校准结果时检索返回 `CALIBRATION_REQUIRED`，不使用旧 `0.80` 或猜测的新常量。产品报告带出实际策略ID和门槛，以便冻结质量报告追溯。
6. 独立校准成功不等于 #189 验收通过。取得协调窗口后，先验证契约、再执行原冻结质量门；不达标仍保留 FAIL 和下游阻塞，不循环用冻结题调参。
