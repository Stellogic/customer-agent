## 实际阻塞与最小验证假设

`KnowledgeRetrievalService.search` 先执行 `answerability.requireCalibrated()`；当前资源仍为 `PENDING_CALIBRATION`，因此默认检索报 `CALIBRATION_REQUIRED`。这是 A 没有得到可用参数后的显式停止，不是可通过删除检查解决的解析缺陷。`knowledge_evaluation.metrics` 按最终 `results` 是否为空计算拒答，`run_query` 将非预期 HTTP 故障直接报错。因此不能将服务错误算正确拒答，也不能换成最终回答的指标。

[已有 A 阶段证据汇总](issue-190-post-a-decision.md)记录：训练144题、校准72题的有答案候选 Recall 都为1，MRR分别0.863426/0.824074；无答案题也都有非空 Top5。固定四特征方案没有可行阈值。这些是已见合成数据的旧观测，说明主要缺口在拒答区分，不能推导冻结集可通过；本轮未重算、未读冻结或留出内容。

**当前没有证据充分、可以直接交付的替代路线。** 若协调决定再进行一次有界验证，建议只考虑现成离线 `BAAI/bge-reranker-base` 的 query/passage 联合评分，不训练另一层分类器、不接云判断、不改变原 RRF 顺序。唯一假设是：合法 Top5 的最大联合相关分能否用一个独立确定的界限区分有答案与相关但无答案。官方只证明它用于相关性排序，**不保证可回答性**，尤其可能误接“主题相同但缺必要事实”，也可能漏掉跨片段组合；这正是必须先验证、不能先接产品的原因。[BGE 官方说明](https://bge-model.com/bge/bge_reranker.html)、[模型卡](https://huggingface.co/BAAI/bge-reranker-base)给出中英模型、278M参数、约1.11GB权重及 Transformers 用法。

最小改动限于本地固定模型准备/评分小模块与开发验证脚本；不改 BGE Embedding、全文/向量候选、RRF、权限、数据库迁移、UI或下游。复用现有 Transformers/PyTorch；无云费用，但新增下载、CPU耗时和内存，实际值未采集。本轮**没有实施或批准该新方法**；正式票未要求该模型，只有证明它对拒答门必要且有效才有理由增加这项运行依赖。

若采用，应先另行固定 revision、文件清单、输入截断和单一界限选择规则，再用不含冻结题的开发数据确定一次参数；现有训练/校准已经看过，只能作开发证据。冻结参数后由独立执行者使用未参与方法选择的新审查数据验证，原封存材料不打开。只有有答案 Recall≥0.90、MRR≥0.75、无答案 precision≥0.90/recall≥0.85且权限违规0全部满足，才有理由申请 #189 原质量门；无可行界限或独立验证失败即停止，不按错题再选模型、调参或续接 C。数据规模、版本及规则未完成固定前，不可运行。此建议不是新的规格、自动运行许可或交付承诺。
