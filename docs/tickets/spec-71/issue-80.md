## What to build

把统一身份、两个界面壳、资源授权和长连接边界固化为可重复的真实全栈验收，并记录依赖兼容与 bundle 的实测证据，使后续维护者能够从一个规范入口验证整个功能而不依赖人工演示结论。

## Acceptance criteria

- [ ] 使用隔离 Compose project 和专用合成数据卷启动真实 React、Spring、PostgreSQL 及所需服务，不修改或删除基线资源。
- [ ] 真实浏览器覆盖未登录、客户、仅客服、仅审批人和双角色内部工作人员，并验证两个 Shell、菜单、默认落点和直接 URL 访问。
- [ ] 全栈场景覆盖真实密码登录、Session 恢复、CSRF、主体替换、跨标签页退出、三十分钟过期语义及服务重启后重新登录。
- [ ] 客户场景证明只获得自己的 `CUSTOMER_PUBLIC` 投影；客服场景证明共享队列最小摘要和有效分配；审批场景证明提案范围视图及租约围栏。
- [ ] 双角色场景证明可以进入两个工作区，但本人参与的提案不在队列中，直接领取和最终决定也被拒绝，派生版本不能洗掉参与者。
- [ ] SSE 场景证明六十秒内重新鉴权，并覆盖 Session 失效、客服分配撤销、审批租约失效、提案版本变化及权威快照恢复。
- [ ] 负向场景证明伪造 `X-Synthetic-*` 无效，并区分 401、403、404 与 409。
- [ ] 生产构建记录实际主要 chunk 和客户首屏依赖，证明内部工作区按路由延迟加载；不预设或夸大未经测量的 bundle 数字。
- [ ] 回归客户公开投影、客服工作台、审批视图、审批租约、补偿执行与对账既有不变量。
- [ ] 从仓库根目录运行完整 `pwsh ./scripts/check.ps1` 并通过；验证说明区分真实证据、推断和未验证的未来 OIDC、多实例及生产等级能力。
