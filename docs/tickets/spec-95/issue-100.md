## What to build

按照高保真原型的桌面审批工作台方向，重塑补偿审批队列、领取审批责任和当前有效审批租约下的审批视图。审批详情清晰区分提案摘要、真实提案依据、资格校验、权威金额、政策信息、证据引用、责任链和决定操作。

未领取时不读取或展示审批证据；租约过期、释放、被替换、提案版本冲突、Session 失效或 SSE 重授权失败后立即移除证据和决定按钮。接口没有提供“AI 建议批准”时不得由前端推断或伪造。

## Acceptance criteria

- [ ] 审批队列使用适合桌面端的高密度布局，只展示真实可领取提案摘要。
- [ ] 未取得当前有效审批租约前不读取或展示审批证据和决定操作。
- [ ] 领取成功后，以清晰层级展示真实提案摘要、资格校验、权威金额、政策信息、证据引用和责任链。
- [ ] 不展示接口未提供的“AI 建议批准”、虚构风险评级、客户资料、工单短号或模拟统计。
- [ ] 批准、驳回并转人工和释放审批责任均具有与风险相称的确认；驳回继续要求真实内部理由。
- [ ] 写操作继续携带当前提案版本、内容摘要、审批租约信息和幂等键；响应不确定时恢复权威状态而非普通重试。
- [ ] 租约过期、释放、被替换、版本冲突、Session 失效或 SSE 重授权失败时立即移除证据和决定按钮。
- [ ] 提案 UUID 使用缩略展示并支持复制完整值，不创建虚构 `PRP-*` 编号。
- [ ] 组件可按队列摘要、租约状态、提案摘要、资格校验、证据和决定区适当拆分，但不建立平行的前端授权状态。
- [ ] 行为测试覆盖领取前不预读、领取后审批视图、批准、驳回、释放、租约撤销、版本冲突、结果未知和禁止自审隔离。
- [ ] 前端格式检查、Lint、类型检查、行为测试和生产构建通过。
- [ ] 使用聚焦浏览器验证审批人真实登录、领取、决定确认和租约撤销后清屏的可见行为。
