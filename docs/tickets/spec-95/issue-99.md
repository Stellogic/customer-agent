## What to build

按照高保真原型的桌面内部工作台方向，重塑客服共享队列、升级队列和取得当前有效客服工单分配后的授权详情。使用高密度队列与详情布局表达真实的工单标识、生命周期状态、处理模式、进入时间，以及领取后的客户标识、订单引用、问题描述、公开沟通、调查事实和业务时间线。

领取前摘要与领取后详情必须保持明确权限分界；客服工单分配撤销、无权资源或 SSE 重授权失败后立即移除受保护详情。不存在真实接口的搜索、筛选、分页、回复、转派、解决、导出或订单查询不进入界面。

## Acceptance criteria

- [ ] 客服共享队列和升级队列使用适合桌面端的高密度表格与详情布局，并与内部界面壳视觉一致。
- [ ] 领取前只渲染真实最小摘要，不展示客户、订单、调查事实或其他授权详情。
- [ ] 领取操作具有明确确认与反馈，仅在取得当前有效客服工单分配后请求并展示详情。
- [ ] 授权详情将公开沟通、调查事实和业务时间线清晰分区，不把内部事实误作客户消息。
- [ ] 客服工单分配撤销、无权资源 404、Session 失效或 SSE 重授权失败时立即清除详情与相关操作。
- [ ] 队列与详情只使用真实 DTO 字段，不显示客户姓名、电话、VIP、优先级、风险、虚构 SLA 或模拟统计。
- [ ] 不显示当前 API 不支持的搜索、筛选、分页、回复、转派、解决、导出或订单查询控件。
- [ ] 工单 UUID 使用缩略展示并支持复制完整值，不创建业务短号。
- [ ] 组件可按队列摘要、授权详情、调查事实、公开沟通、业务时间线和连接状态适当拆分，但不复制服务端授权权威。
- [ ] 行为测试覆盖领取前不预读、领取后详情、404、分配撤销、SSE 恢复和陈旧详情清屏。
- [ ] 前端格式检查、Lint、类型检查、行为测试和生产构建通过。
- [ ] 使用聚焦浏览器验证客服真实登录、队列、领取和撤权后清屏的可见行为。
