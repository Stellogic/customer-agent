## What to build

按照高保真原型的客户侧设计方向，重塑客户帮助中心和客户客服工单的完整真实状态体验。围绕订单引用与问题描述创建客服工单，并清晰呈现调查中、等待客户、等待外部信息、人工处理、已解决、已关闭、客户澄清、请求转人工、公开回复、断线与重新同步。

页面只使用客户公开投影中的真实字段，不展示内部调查、审批证据、协议字段或原型模拟数据；对响应不确定的写操作恢复权威结果，而不是鼓励重复提交。

## Acceptance criteria

- [ ] 客户首页、创建表单和客服工单详情采用温暖、轻量、解释性强的原型视觉语言。
- [ ] 创建表单只包含真实支持的订单引用与问题描述，不增加附件、商品详情、联系方式或承诺时间。
- [ ] NEW、INVESTIGATING、WAITING_FOR_CUSTOMER、WAITING_FOR_EXTERNAL、RESOLVED、CLOSED 及 AGENT、HUMAN 使用准确且非技术化的中文状态表达。
- [ ] 当前有效客户澄清请求、澄清回复与恢复查询具有明确下一步和权威结果反馈。
- [ ] 请求转人工及其结果查询保持幂等边界，响应不确定时不提供普通重复提交路径。
- [ ] 已解决和已关闭状态只显示现有真实回复能力，不虚构直接重开或其他操作。
- [ ] 公开沟通与内部事实保持数据和视觉隔离；cursor、generation、schema 等协议字段不展示。
- [ ] 工单 UUID 以稳定缩略形式展示并可复制完整值，不创建虚构业务短号。
- [ ] Session 失效、主体替换或 SSE 恢复失败时清除陈旧客户数据并进入权威状态。
- [ ] 行为测试覆盖创建、恢复、主要生命周期状态、澄清、转人工、回复、结果未知和撤权清屏。
- [ ] 前端格式检查、Lint、类型检查、行为测试和生产构建通过。
- [ ] 使用聚焦浏览器验证客户真实登录、创建客服工单、至少一个交互状态和连接恢复视觉。
