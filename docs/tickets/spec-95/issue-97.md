## What to build

在已落地的视觉基础上，统一客户登录、内部登录、客户界面壳、内部界面壳和双角色工作区选择页。客户与内部工作人员使用一致的 Stellogic 品牌语言，但继续拥有彼此独立的导航与数据投影。

本地演示账号继续由后端动态提供并只用于填充真实登录表单。保持当前 Session、CSRF、页面 capability、静态工作区映射、默认落点、受控返回地址、退出清理、跨标签页清理、路由延迟加载和双角色选择页不预读业务数据等行为。

## Acceptance criteria

- [ ] 客户登录、内部登录、客户界面壳、内部界面壳和双角色工作区选择页采用原型视觉语言且语境清晰分离。
- [ ] 演示账号继续动态读取，仅在后端提供时显示；不写死原型账号或密码，不绕过真实登录提交。
- [ ] 客户、仅客服、仅审批人和双角色内部工作人员继续进入既有确定性落点，缺少 capability 时保持 403。
- [ ] 双角色选择页只展示授权入口，不读取客服或审批业务数据。
- [ ] 受控返回地址、旧路由重定向、Session 恢复、退出、主体替换和跨标签页清理行为保持不变。
- [ ] 客户与内部工作区继续按路由分离和延迟加载，共享视觉组件不构成授权边界。
- [ ] 组件拆分只围绕两个界面壳、登录体验和工作区入口的真实复用，不建立跨身份完整 DTO 的通用页面组件。
- [ ] 行为测试覆盖四类身份与未登录状态下的可见导航、落点、403 和不预读行为。
- [ ] 前端格式检查、Lint、类型检查、行为测试、生产构建及 bundle 聚焦检查通过。
- [ ] 使用聚焦浏览器验证真实密码登录、两个界面壳、双角色选择和退出后的可见状态。
