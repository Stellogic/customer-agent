## What to build

把补偿额度竞争从单工单提升为订单范围仲裁。属于同一订单的多张工单可以分别形成提案，但 Spring 必须汇总该订单全部已执行、已批准、待审批与有效额度预占，防止重复消费额度。

## Acceptance criteria

- [ ] 权威总可补偿额度按订单和政策计算，并纳入该订单全部客服工单的既有补偿事实。
- [ ] 有效额度预占总额覆盖同订单全部有效审批与结果不明确执行，剩余额度只扣减一次。
- [ ] 两张或多张工单并发提案、审批和预占时，真实 PostgreSQL 事务最多允许合法额度范围内的组合成功。
- [ ] 单张工单不能通过不同问题类型、提案版本或重试绕过订单总额。
- [ ] 审批证据快照保存决定时的权威总额、有效预占和剩余额度，并在决定提交时重新核对。
- [ ] 驳回、提案失效、执行成功、确认失败和待对账正确更新订单范围可用事实。
- [ ] 客户、客服和审批人各自只看到授权投影，不因订单汇总获得其他工单完整对话。
- [ ] 并发、响应丢失和重放测试证明不会产生超过订单上限的补偿或重复执行。
