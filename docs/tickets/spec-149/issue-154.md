## What to build

处理受理路由中的两类异常：疑似重复问题必须由客户确认是否继续既有工单；一次描述涉及多个订单时必须逐个订单续办，不能跨订单一次批量建单。

## Acceptance criteria

- [ ] 场景一：客户确认疑似重复问题与既有未关闭工单相同，系统导航到既有工单且不创建重复工单。
- [ ] 场景二：客户否认疑似重复问题，系统允许把它作为独立新问题继续确认并创建工单。
- [ ] 重复问题匹配只使用同一客户、同一订单、未关闭工单的最小摘要，不能自动合并或读取越权对话。
- [ ] 场景三：一次描述包含多个订单时，系统先完成当前订单的拟建工单集，再使用保留描述继续下一个订单。
- [ ] 场景四：任何确认操作都不能一次跨订单批量创建工单；每个订单分别确认和原子提交。
- [ ] 多订单续办不要求客户重复输入原始描述，但必须重新确认下一订单候选与问题集合。
- [ ] 重复确认和多订单续办在刷新、重试与竞态下保持幂等，不产生静默遗漏。
- [ ] 对应路由异常 UI 包含清晰解释、继续旧工单、创建新工单和继续下一订单的桌面/窄屏状态。
