## What to build

只补齐前序纵切片尚未覆盖的高保真原型区域、状态画廊和“开发中”入口。不得在本票集中重写已经由受理、多工单、流式对话、客服处理、补偿、审批或知识纵切片完成的核心页面。

## Acceptance criteria

- [ ] 新增并完成 `/states` 状态画廊，逐项覆盖：首次 Loading skeleton、Empty 队列、保留旧数据的 Error、403、404、实时连接断开、正在重新同步、审批租约过期、操作成功和操作结果未知。
- [ ] 完成独立 `/403` 与 `/404` 路由，提供符合身份边界的说明和返回入口，不加载受保护业务数据。
- [ ] 补齐客户壳剩余区域：顶部“帮助文档”入口、帮助中心信任说明、AI/人工/补偿三块说明区域及相关帮助链接；未实现内容点击明确显示“开发中”。
- [ ] 补齐内部壳剩余快捷入口：我的工单、SLA 监控、知识库导航、模板中心、侧栏收起、通知中心和重新同步反馈；没有真实能力的入口显示“开发中”。
- [ ] 补齐客服详情剩余非核心入口：转派、更多操作、查看订单、查看物流、联系客户、相似案例和建议动作；仅已实现能力连接真实后端，其余显示“开发中”。
- [ ] 补齐审批页面剩余非核心入口：更多筛选、导出、政策详情、提案日志、物流轨迹、资格检查明细和完整对话；不扩大审批视图，未实现操作显示“开发中”。
- [ ] `/help/login`、`/internal/login`、`/internal`、客户受理与工单对话、订单工单组、客服队列与详情、审批队列与详情、知识检索页均明确属于既有或前序票；本票不得重新设计其业务流程、API 或整体视觉结构。
- [ ] 所有剩余区域匹配原型的森林绿、米白、字体、间距、壳层和反馈语言，并覆盖桌面与窄屏、键盘焦点和基础屏幕阅读器语义。
- [ ] “开发中”操作不发送伪造成功事件、不改变后端状态，也不伪造发送、领取、审批、补偿或知识发布结果。
- [ ] 真实 Chromium 截图或等价视觉证据逐项映射上述清单，验收报告明确已覆盖与刻意不返工区域。
