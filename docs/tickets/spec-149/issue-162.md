## What to build

仅对 Spring 版本化白名单中的低风险场景建立五分钟自动解决候选。完整回复持久化后开始计时，客户任何新回复都取消候选；到期时根据最新工单版本重新校验全部条件。

## Acceptance criteria

- [ ] 自动解决候选要求低风险、事实充分、明确结论、无待办动作、无待审批补偿和完整回复已持久化同时成立。
- [ ] 第一阶段允许场景只包括无争议无待办的权威状态解释、纯规则说明和已完成无争议的非补偿性核对。
- [ ] 签收未收到、疑似丢件、重复扣款、退款异常、地址修改、取消订单、补偿、事实冲突和等待外部信息均不能自动解决。
- [ ] 五分钟期限由 Spring 持久化，刷新、重登、SSE 中断和服务重启不重置。
- [ ] 客户任何新回复或“仍需帮助”操作立即取消当前候选。
- [ ] 恰好截止时间的新回复与调度任务通过工单锁和版本仲裁，已被 Spring 接受的新回复优先。
- [ ] 到期任务重新校验全部条件；新增待办、补偿、模式变化或事实失效会阻止解决。
- [ ] Agent 自动解决后沿用七十二小时关闭等待期；人工手动解决不受五分钟限制。
- [ ] 客户 UI 明确展示倒计时、取消入口、已取消、重新评估和已解决状态，并覆盖桌面与窄屏。
