## What to build

作为纯发布验收票，使用固定 DeepSeek 模型、合成业务场景、预先冻结的调用次数、供应商尝试和成本上限，通过同一真实浏览器产品接缝证明自然受理、多轮调查、事实充分、知识引用和失败转人工真实可用。

## Acceptance criteria

- [ ] 本票只增加真实模型验收场景、预算门禁和证据文档，不实现或修补跨模块产品功能。
- [ ] 开始调用前冻结模型名称、提示版本、schema 版本、场景集、逻辑调用上限、供应商尝试上限和总成本上限。
- [ ] 场景覆盖自然语言订单与问题识别、同订单多个问题、不同合法调查路径、客户追加消息、知识引用和安全转人工。
- [ ] Spring 继续校验证据充分、业务事实、资格、金额、状态和副作用；模型不能获得审批或执行权限。
- [ ] 真实浏览器只通过 Spring API/SSE 观察结果，不用独立 provider 请求冒充产品验收。
- [ ] 按 #149 rag-layered-v2 分别记录结构合法性、引用真实性、语义充分性与实际回答的无答案拒答 precision/recall，并记录安全不变量、延迟、调用次数、尝试次数、token 与成本；完整分母保留失败，不把格式故障计作正确拒答。不保存原始 prompt、响应、思维链或密钥，沿用本票原证据边界。
- [ ] 供应商不可用、余额不足、限流、预算耗尽、模型失败或契约不满足时诚实失败并保留证据。
- [ ] 失败时不降低通过门槛、不更换模型、不扩大预算、不回退 fixed fake，也不把未运行写成通过。
- [ ] 发现产品缺口时回到对应实施票修复；本票保持纯验收边界。
- [ ] 最终报告明确区分确定性全栈证明、真实 DeepSeek 证明和仍未验证的生产级范围。
