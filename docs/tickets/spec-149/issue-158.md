## What to build

允许客户在 Agent 正在生成时继续追加公开消息，并通过 Spring 权威版本建立新的 Agent 处理代次或等价围栏，使基于旧上下文的未完成输出、迟到工具动作和迟到业务副作用全部失效。

## Acceptance criteria

- [ ] 客户输入器在 Agent 处理中保持可用，不要求等待当前回复完成。
- [ ] 每条客户消息使用稳定消息身份和幂等请求语义，重复提交不会产生重复公开消息。
- [ ] Spring 接受新消息后建立新的权威处理版本，并把最新完整对话交给后续 Agent 运行。
- [ ] 旧代次不能继续追加公开内容、创建澄清、提交结论、形成补偿提案或请求转人工。
- [ ] 首字前、生成中、完成提交边界和工具调用期间的新消息竞态均由 Spring 仲裁。
- [ ] 客户人工偏好、`HUMAN` 处理模式和权限撤销继续优先于任何 Agent 结果。
- [ ] 产品事件能让客户端区分已接受的新消息、旧生成终止和新生成开始，不暴露内部 generation 标识。
- [ ] 对应输入和取消状态覆盖桌面、窄屏、发送中、重试、冲突与错误反馈。
