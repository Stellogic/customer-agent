## What to build

持久化尚未确认的受理对话，使客户在刷新、重新登录、SSE 断线或稍后返回时继续原受理；七个自然日后归档，恢复归档内容时重新确认可能变化的订单事实。

## Acceptance criteria

- [ ] 受理消息、候选订单、拟建工单集、澄清状态和稳定请求身份由 Spring 权威持久化。
- [ ] 页面刷新、路由切换、重新登录和 SSE 中断不会丢失或自动确认受理。
- [ ] 同一客户只能读取自己的活动或归档受理，不可枚举其他客户数据。
- [ ] 七个自然日边界使用可控时钟验证；到期只归档，不创建工单或启动 SLO。
- [ ] 恢复归档受理时重新校验订单权属、订单候选和变化事实，旧确认不能直接重放。
- [ ] 并发恢复、重复确认和过期竞态由稳定版本仲裁，不创建重复工单。
- [ ] 客户 UI 提供活动受理、已归档、恢复中、事实已变化、加载失败和无受理记录状态，并覆盖桌面与窄屏。
