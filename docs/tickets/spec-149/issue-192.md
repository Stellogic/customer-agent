## What to build

补齐正式客户壳中尚未覆盖的帮助入口、信任说明和 AI、人工、补偿能力解释，使客户能够理解系统边界，并对尚未实现的帮助内容得到明确而诚实的“开发中”反馈。

## Non-goals

- 不重新设计客户受理、订单工单组、工单对话、流式回复、自动解决或知识来源业务流程。
- 不新增伪造的帮助后台、知识发布或业务动作。
- 不改变 Spring 授权与客户数据投影。

## Acceptance criteria

- [ ] 客户壳提供一致的“帮助文档”入口，并在帮助中心呈现清晰的信任说明及 AI、人工、补偿三块能力边界。
- [ ] 已有真实帮助内容连接到正确页面；未实现内容点击后明确显示“开发中”，不发送写请求或伪造成功事件。
- [ ] 文案准确区分 Agent 建议、人工责任、补偿待审批与已批准或已执行，不扩大当前产品承诺。
- [ ] 客户壳保持与既有客户受理、订单工单组和对话页面一致的森林绿、米白、字体、间距与响应式层级。
- [ ] 真实 Chromium 验收覆盖桌面、窄屏、键盘焦点、基础屏幕阅读器语义和“开发中”无副作用证据。
