## What to build

让负责客服从 Spring 允许的标准补偿方案中选择类型和理由，形成补偿提案并提交人工审批。客服不能任意覆盖金额或方式，客户只能看到准确的待审批状态。

## Acceptance criteria

- [ ] 只有当前负责客服可以读取本工单当前允许的标准补偿方案。
- [ ] 方案类型、资格、金额、上限和政策版本由 Spring 权威计算，Agent 或客服不能提交任意金额覆盖。
- [ ] 客服选择方案和受控理由后形成新的补偿提案版本，并遵守幂等、不可变修订和参与者继承规则。
- [ ] 超出标准方案的诉求进入独立例外补偿申请，不复用普通提案接口绕过授权。
- [ ] 提交审批后客户可以看到安全的类型、金额和“待审批”，但不能被告知已经批准或执行。
- [ ] 审批租约、禁止自审、驳回转人工、批准后执行和待对账语义保持不变。
- [ ] 模式变化、旧提案版本、额度不足、事实失效和重复提交均产生稳定可恢复结果。
- [ ] 客服补偿 UI 和客户待审批投影同步复刻原型信息层级，并覆盖桌面、窄屏、loading、empty、error 和提交结果未知。
