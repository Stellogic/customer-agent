## What to build

复用已建立的转人工业务能力，在 Agent 无法安全继续调查时自动停止自主处理。系统保留结构化调查摘要和受控理由码供未来获授权客服接手，但本切片不实现完整人工客服处理页面。

## Acceptance criteria

- [ ] 受控场景覆盖工具重试耗尽、关键事实冲突、工具数据不符合结构、缺少必需事实和当前 MVP 不支持的业务场景。
- [ ] 每个触发条件映射到封闭理由码；异常、stack trace、prompt、模型输出、自由形式推理和原始工具 payload 不进入客户消息或浏览器事件。
- [ ] 安全转人工与客户主动转人工使用同一原子业务转换：HUMAN 处理模式、当前处理代次撤销、固定公开说明、共享队列摘要和审计事件。
- [ ] 持久化的调查摘要只包含未来获授权客服接手所需的结构化事实、证据引用和受控结论，不复制完整原始工具结果。
- [ ] 有副作用风险的步骤在转人工前后均使用幂等身份和当前处理代次校验；迟到调用不能改变工单或发布消息。
- [ ] 边界内的暂时性工具错误按已配置次数重试；只有预算耗尽或被分类为不安全时才转人工，测试不依赖真实等待。
- [ ] 固定假模型与工具用例确定性覆盖每个转人工分支、重复触发和触发条件并发。
- [ ] 客户界面与客服共享队列只呈现各自获授权的信息，完整调查摘要目前没有面向未分配客服的读取入口。
