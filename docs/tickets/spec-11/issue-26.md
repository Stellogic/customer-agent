## What to build

让客服内部工作台可靠恢复共享队列与共享升级队列的最小摘要，同时维持“队列可发现不等于工单详情授权”的边界。本切片仍不实现客服领取和完整人工处理页面。

## Acceptance criteria

- [ ] SUPPORT_WORKBENCH 使用与客户和审批视图不同的投影形状、epoch、sequence、快照与 SSE 端点。
- [ ] 普通共享队列和 SLA 违约共享升级队列只呈现规格确认的最小摘要；转人工理由详情、调查摘要和完整客服工单不随队列公开。
- [ ] 重复、旧序号、缺口、epoch/view/schema 不兼容、裁剪历史和非法 payload 使用与契约一致的忽略或快照重置行为。
- [ ] 当前无有效工单分配的客服即使看见队列条目，也不能通过详情 API、猜测标识或旧浏览器缓存读取客户沟通、内部记录、调查事实或业务时间线。
- [ ] 客户与审批人不能访问客服工作台路由、快照或事件流；隐藏菜单和游标均不构成授权。
- [ ] 转人工、SLA 违约或队列移除与快照/订阅并发时，重放和实时流最终收敛到 Spring 权威状态且不出现幽灵条目。
- [ ] 断线和 reset_required 明确显示可能过期并重新取快照，避免浏览器自动重连循环持续应用错误状态。
- [ ] 前端行为测试覆盖角色路由、断线恢复、键盘/焦点、窄屏和基础屏幕阅读器语义；产品界面没有自由角色切换器。
