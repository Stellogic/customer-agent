## What to build

让客户在独立帮助中心提交物流延迟问题，并在一次可查询、可追踪的公开沟通中看到工单已被受理。Spring 是客服工单、消息、首次响应、授权和审计的唯一业务权威；本票不启动 Agent 调查。

## Acceptance criteria

- [ ] 客户可以使用合成身份和稳定请求身份提交物流延迟问题；首次请求原子创建客服工单、客户公开消息、首次响应事实和对应审计事件。
- [ ] 相同请求身份和相同参数重复提交返回既有结果；相同身份配合不同参数返回明确冲突，并覆盖真正并发的重复请求。
- [ ] 客服工单使用已确认生命周期和独立处理模式；首次响应是时间事实而不是新的生命周期状态。
- [ ] 客户帮助中心先读取完整 CUSTOMER_PUBLIC 权威快照及 epoch:sequence 游标，再接收同视图的基础 SSE 增量。
- [ ] 客户只能读取自己的公开沟通、公开状态和公开进度；其他客户的工单返回不可枚举的拒绝结果。
- [ ] 客户投影及浏览器事件不包含内部记录、调查事实、提案草稿、审批责任链、Agent thread/run/checkpoint 或原始工具数据。
- [ ] SSE 断开不会回滚已提交工单；刷新页面能够从 Spring 权威快照恢复相同结果。
- [ ] 自动化验收跨越 React 表单、Spring API、真实 PostgreSQL 迁移和授权边界，且不依赖精确自然语言措辞。
