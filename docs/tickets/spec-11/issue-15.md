## What to build

在已运行的调查链路上加入完整物流延迟补偿政策。Agent 只提交结构化建议，Spring 独立判断资格、方式和金额，并形成可供人工审批的不可变补偿提案版本与最小审批证据快照。

## Acceptance criteria

- [ ] 确定性测试覆盖延迟立即低于、等于和高于 24、48、72 小时，政策区间互斥且边界与 #11 一致。
- [ ] 24 至不足 48 小时生成 10 CNY 优惠券，48 至含 72 小时生成 20 CNY 优惠券，超过 72 小时生成按实付金额 10%、上限 50.00 CNY 的模拟部分退款。
- [ ] 金额使用十进制定点语义并精确到分，覆盖封顶和四舍五入；Agent 提交金额不构成权威金额。
- [ ] 取消、未支付、已全额退款、同原因已有补偿、可补偿额度不足或并发预占冲突时，Spring 拒绝不合法提案。
- [ ] 补偿提案版本绑定客服工单、订单、延迟事实、方式、金额、理由码、证据引用、审批证据快照、政策版本和内容摘要，创建后不可修改。
- [ ] 关键内容变化创建新版本并使旧版本失效；同一延迟原因最多存在一个有效待审批或已批准未完成的补偿意图，使用真实 PostgreSQL 约束验证并发。
- [ ] 80 小时、实付 268.00 CNY 的合成订单形成 26.80 CNY 模拟部分退款提案版本。
- [ ] Spring 接受提案后结束 Agent 处理代次；客户只看到等待审批的公开说明，不获得提案草稿、证据或审批详情；关键变化与审计事件同事务提交。
