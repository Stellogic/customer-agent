## What to build

让系统以可控业务时钟计算首次响应和解决时长，在风险出现时通知当前负责客服，并把已违约客服工单作为最小摘要投影到客服共享升级队列，同时保持生命周期、处理模式和权限边界不变。

## Acceptance criteria

- [ ] 首次响应目标为创建后 15 个连续自然分钟且从不暂停；在 80% 和 100% 边界分别形成预警和不可撤销违约事实。
- [ ] 解决目标为累计 24 个连续自然小时；仅 WAITING_FOR_CUSTOMER 暂停，WAITING_FOR_EXTERNAL 继续计时。
- [ ] 从等待客户恢复时立即重新计算剩余预算，覆盖恢复瞬间跨越 80% 或 100% 阈值；重开延续原累计解决时长。
- [ ] 达到 RESOLVED 时停止解决计时；已经发生的预警或违约不会因后来解决而删除。
- [ ] 存在当前负责客服时，SLA 预警只通知该客服；预警不创建分配、不授予详情访问。
- [ ] SLA 违约使客服工单进入客服共享升级队列；队列只暴露已确认的最小摘要，既不改变生命周期或处理模式，也不授予补偿权限。
- [ ] 无当前有效分配的客服可以看到队列摘要但不能读取完整客服工单、公开沟通、内部记录或调查事实。
- [ ] 使用可控时钟和真实 PostgreSQL 覆盖恰好边界、等待状态切换、重复调度以及并发状态变化；SLA 事实与审计事件原子提交。
