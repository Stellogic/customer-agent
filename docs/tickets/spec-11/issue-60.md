## 问题

React 客户澄清提交当前没有严格区分确定性 HTTP 拒绝与响应不确定性，可能把明确失败错误地送入恢复对账，导致错误文案、无意义查询，或错误延长稳定 `resumeRequestId` 的生命周期。

## 范围

仅修复客户澄清提交前端行为；浏览器继续只访问 Spring：

- `422`：显示输入校验错误，不查询 resume 恢复端点。
- `409`：刷新 Spring 权威客户快照，并说明澄清已失效或工单状态已变化；不查询 resume 恢复端点。
- `401` / `403` / `404`：分别按认证、授权、资源不存在状态处理；不查询 resume 恢复端点。
- 仅网络错误、连接中断，以及合理定义的 `5xx` / 未知提交结果进入恢复对账。
- 对账必须复用原始稳定 `resumeRequestId`；确定性拒绝和最终成功后不得错误保留该 key。
- 不改变 Spring 业务权威边界，不让浏览器访问 Agent Server。

## 验收标准

- [ ] 前端行为测试覆盖 `409`、`422`、`401/403/404`、`5xx`、响应丢失与成功路径。
- [ ] 测试断言用户文案、是否调用恢复查询、`resumeRequestId` 的复用与清理生命周期。
- [ ] `409` 会重新获取 Spring 客户权威快照。
- [ ] `422` 与 `401/403/404` 不进入恢复对账。
- [ ] 网络/连接中断、定义内的 `5xx` 或未知结果才进入稳定 key 对账。
- [ ] 浏览器构建与网络边界仍只包含 Spring API。
- [ ] 从仓库根运行 `pwsh ./scripts/check.ps1` 通过。

## 非目标

- 不修改 Agent/LangGraph 恢复协议或 Spring 业务状态机。
- 不顺手处理其他历史审阅项，不创建后继任务。
