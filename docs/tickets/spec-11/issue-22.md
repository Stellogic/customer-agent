## What to build

让持有当前审批租约的审批人批准特定补偿提案版本。Spring 在最终授权事务中重新读取全部权威事实，原子形成最终审批、额度预占和唯一 READY 补偿执行；审批仍不等于执行成功。

## Acceptance criteria

- [ ] 批准命令绑定当前提案版本、内容摘要、租约 token/version 和稳定决定请求身份；审批备注可选。
- [ ] 同一事务重新读取并验证订单支付/取消/退款状态、延迟事实、政策版本与档位、Spring 重算金额、可补偿额度、既有补偿意图和并发预占。
- [ ] 任何事实漂移、政策变化、额度不足、版本过期或被替换均拒绝批准，使旧版本失效，并要求新提案版本后才能再次审批。
- [ ] 成功批准原子记录最终审批、额度预占、唯一 READY 补偿执行及审计事件；补偿执行使用稳定执行身份和幂等键。
- [ ] PostgreSQL 唯一约束保证同一提案版本、订单延迟原因和补偿意图不会因并发产生第二个有效执行或超额预占。
- [ ] 相同决定请求重试返回原结果；相同身份不同参数、批准/驳回竞争和两个提案争抢额度时均得到确定性结果。
- [ ] 批准完成后审批视图和操作立即撤销；客户仅看到等待补偿处理的公开状态，不被告知执行已成功。
- [ ] 任何业务角色都不能撤销最终审批，也不能调用执行、普通重试或对账操作；审批人无法取得补偿执行器身份。
