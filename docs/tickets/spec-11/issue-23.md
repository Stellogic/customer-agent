## What to build

让受限补偿执行器异步推进已经批准的补偿执行，覆盖优惠券和模拟部分原支付方式退款的正常成功路径。Spring 只有在成功被权威确认后才发布客户结果并将客服工单置为已解决。

## Acceptance criteria

- [ ] 补偿执行器只能读取和推进分配给自身的补偿执行、追加补偿执行尝试，不能修改提案、审批、对象、金额、方式或审批证据。
- [ ] 执行使用由已批准提案版本派生的稳定 executionId 与 idempotencyKey，并绑定关键参数摘要；相同身份不同参数被拒绝。
- [ ] 合法状态按 READY → PROCESSING → SUCCEEDED 推进；非法跳转、重复投递和两个 worker 并发领取得到确定性结果。
- [ ] 10 CNY、20 CNY 优惠券与模拟部分退款均有正常成功路径；本项目不调用真实支付、退款或物流系统。
- [ ] 重复执行投递或执行响应重放返回同一业务结果，不创建第二个优惠券、模拟退款或补偿执行。
- [ ] 只有 Spring 确认 SUCCEEDED 后才发布客户最终结果并把客服工单置为 RESOLVED；审批成功本身不能提前显示为补偿成功。
- [ ] 客户最终结果包含补偿方式和金额；部分退款只显示掩码支付去向，不显示支付 token、凭据或内部执行标识。
- [ ] 执行状态、执行尝试、客服工单转换和审计事件保持事务一致；自动化测试覆盖优惠券、部分退款、重复投递和并发 worker。
