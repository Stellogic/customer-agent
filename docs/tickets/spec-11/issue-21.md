## What to build

让持有当前审批租约的审批人驳回特定补偿提案版本。驳回要求内部理由，并原子结束审批责任、转人工和发布固定客户说明；它不得创建额度预占或补偿执行。

## Acceptance criteria

- [ ] 驳回命令必须携带当前提案版本、内容摘要、租约 token/version、稳定决定请求身份和非空内部理由。
- [ ] 提交时使用服务器时间重新验证提案待审批状态、版本、有效期、审批人和租约；任一不匹配均拒绝。
- [ ] 相同决定身份和相同参数重复提交返回既有决定；相同身份用于不同决定、理由或版本时返回冲突。
- [ ] 成功驳回在一个事务内记录最终决定与内部理由、不创建额度预占或补偿执行、切换为 HUMAN、撤销当前审批责任、发布固定客户转人工说明、加入共享队列并追加审计事件。
- [ ] 驳回理由只对未来获授权人工处理与审计引用可用，不进入客户投影或共享队列摘要。
- [ ] 覆盖批准/驳回并发、租约过期瞬间提交、旧版本提交、release 后提交和重复浏览器请求。
- [ ] 决定成功、提案失效或责任结束后，审批视图中的证据与操作立即不可再读取，旧页面不能继续提交。
- [ ] 审批人不能通过驳回流程执行、重试、对账或撤销任何补偿。
