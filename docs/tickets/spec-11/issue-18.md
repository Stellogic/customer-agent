## What to build

让客户能够明确要求由人工继续处理当前客服工单。Spring 原子记录客户人工偏好、切换处理模式、撤销当前 Agent 处理代次、发布固定公开说明并加入客服共享队列；任何旧 Agent 副作用都不能越过新的业务责任边界。

## Acceptance criteria

- [ ] 客户可以使用稳定请求身份对自己的当前客服工单请求人工处理；相同请求重试幂等，不同参数复用身份返回冲突。
- [ ] 一个事务内记录客户人工偏好、把处理模式改为 HUMAN、撤销当前 Agent 处理代次、持久化转人工原因、发布固定客户消息、加入最小摘要共享队列并追加审计事件。
- [ ] 客户人工偏好与客服工单生命周期正交，不把转人工伪装成新的生命周期状态。
- [ ] 客户人工偏好未被客户明确解除时，系统不得自动恢复 Agent 处理；本票不实现客服交回 Agent。
- [ ] 转人工与客户澄清回复、Agent 工具写入或公开消息并发时，数据库只接受一个当前业务权威结果。
- [ ] 被撤销处理代次的迟到工具调用、调查结果和公开消息均被拒绝并追加审计，不能污染任何产品投影。
- [ ] 客户只看到固定转人工说明；客服共享队列只看到最小摘要，未分配客服仍无详情访问权。
- [ ] 前端验收覆盖请求人工、重复点击、断线后查询、迟到 Agent 事件和客户视图不泄露内部原因。
