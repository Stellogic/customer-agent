## What to build

让客户从自然受理进入物流延迟工单后，程序读取规则明确的必需事实并构造真实证据关系，模型在需要时补查、追问并组织回复，最终得到有依据的无补偿结果或待审批提案。无需让模型逐次排列必读工具、重复填写固定证据关系，也不要求读取与本问题无关的订单规则。

本票建立并实际跑通第一个场景化产品切片，不交付独立规则平台或只有接口的基础设施。先在切片内完成必要的事实策略接缝整理，再接通物流延迟的完整路径；其余场景保留可运行的现状，由后续票迁移。对外产品行为和权限保持，内部若需兼容过渡，必须有明确消费者与退出条件。

## Acceptance criteria

- [ ] 回读已交付 #226 与最新主线，在不覆盖共享改动的前提下开始；不得无差别合并 PR #214 或顺带关闭 #174。
- [ ] 将 #227 已确认的职责决定落入正式 ADR 和领域文档，保留旧自治决策历史及其余权限边界；复用已准备的 ADR 内容并核对当前编号，不另做产品方向决策。
- [ ] 物流延迟的必需事实和机械证据对应关系来自 Spring 权威策略及业务依据，不在 Agent 提示中维护独立演化的第二份规则清单。
- [ ] 程序执行本场景明确必需的真实授权读取，仅从当前工单有效代次的已取得事实构造必需证据关系；缺失事实不得填默认值或伪造引用。
- [ ] 模型不再为每个必读工具单独作机械选择，也不再机械补写必需证据映射；保留真实诉求理解、额外调查、必要追问、补充证据选择及自然回复，遵守现有授权和预算。知识语义判断不被程序映射替代。
- [ ] 从实际能力调用和事实记录证明：物流延迟无需读取订单规则即可完成无补偿或待审批路径；不以私有方法、唯一工具顺序或模型逐字文案为测试目标。
- [ ] 结论、回复与 Spring 复核使用实际场景事实，支付相关资格、已有补偿、待办及适用政策校验保持；无补偿不误报补偿，待审批不声称已批准或已执行。
- [ ] 场景化策略接入调查、事实归一化、业务判断、公开回复及澄清恢复；确定性模型与 DeepSeek 使用相同场景契约。其他既有场景保持可运行，不能让普通测试继续全读来掩盖本场景真实路径裁剪。
- [ ] 缺少必需事实、事实过期、越权或冲突仍被拒绝；只补当前修改涉及的有效回归，不引入无关防御框架。
- [ ] 为本路径记录可定位的失败类别、缺少的事实或适用性类别及能力/调用归属；供应商、解析、发布和业务拒绝可区分，不保存原始 prompt、响应、思维链或秘密，也不改判历史运行原因。
- [ ] 通过真实 Chromium 的受理、确认、调查及公开回复路径证明两个物流终点；低风险自动解决候选、客户取消候选、代次隔离、人工审批与执行约束继续通过相关回归。可使用确定性模型作本票端到端证据，不能据此宣称真实模型稳定。
- [ ] 完成针对实际缺陷的回归、Standards/Spec 审查和对应最终版本的完整规范化门禁，达到本票要求后独立交付。受控真实验证由后续核心验证票汇总，不因本票创建启动模型调用。
