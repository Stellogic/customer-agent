# 一个 React 应用使用两个界面壳

客户、客服和审批人使用同一个 React 应用，以复用设计系统、API 客户端、构建、测试和部署；应用内保留彼此独立的 `CustomerShell` 与 `InternalShell`，不让客户与内部工作人员共享导航或数据投影。正式路由为 `/help/**`、`/internal/support/**` 和 `/internal/approvals/**`，旧 `/support` 与 `/approver` 仅临时重定向；Spring 只返回参与者类型、角色和 capabilities，前端以静态映射生成菜单与默认落点，后端不下发 React 路由定义或路径。Spring API、客服工单分配、审批租约和补偿提案版本继续承担权威授权。

相比三个独立前端，该结构减少重复建设；相比所有参与者共用一个界面壳，它降低权限分支和信息泄露风险。各业务区域按路由延迟加载以控制客户首屏包体，但代码分包不构成安全边界；未来若隔离要求提高，可以在同一仓库改为客户与内部工作台两个构建入口。

前端根据当前身份执行确定性落点映射：客户进入 `/help`，仅客服进入 `/internal/support`，仅审批人进入 `/internal/approvals`，双角色内部工作人员进入不加载业务数据的轻量 `/internal` 选择页。未登录访问受保护页面时只接受经过同源路径校验的返回地址；缺少页面 capability 时显示 403，无权知道资源存在时 API 返回 404，已获可见性但审批租约失效或版本冲突时返回 409。

旧 `/support` 与 `/approver` 只在首个包含统一工作台的版本中重定向并标记弃用，下一次明确的路由清理版本在确认仓库链接、测试和演示入口均已迁移后删除，不按日历时间自动失效。
