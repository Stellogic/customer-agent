# 通过自然语言受理并在确认后创建工单集

客户不需要先选择订单或问题类型，也不需要逐个重复描述诉求。Agent 在正式工单创建前的可恢复受理对话中理解自然语言、依据当前客户可见的订单摘要提出订单候选，并把同一订单中的多个独立问题整理为拟建工单集；低置信度判断需要自然澄清，客户可以用自然语言或快捷按钮一次确认，随后 Spring 原子地为每个新问题创建一张客服工单。既有未关闭的疑似同一问题必须经客户确认后才继续原工单。共同受理内容保存为各新工单引用的不可变记录，后续对话彼此独立。客户和内部工作人员都按订单分组查看工单，但每张工单继续拥有独立的状态、负责人、处理模式和补偿审批边界，并可并行运行独立 Agent；其他同订单工单只通过最小结构化摘要提供协调信号。确认前不创建正式工单，也不启动工单服务级别目标；未完成受理保留七天，自动受理失败时使用无工单处理权限的受理协助请求让客服接手。这一选择用更自然的入口换取了独立受理阶段及其恢复、超时和审计语义。
