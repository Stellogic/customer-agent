# Issue #29：3–5 分钟演示与录屏后备

## 演示前准备

1. 只使用仓库内的 `customer-demo`、`approver-demo` 和 `ORDER-DELAY-E2E-RECONCILIATION` 合成数据。
2. 执行 `pwsh -File scripts/smoke.ps1 -Reset`，确认两条命名验收、V1→V18 迁移和敏感串扫描均通过。
3. 打开客户帮助中心和审批工作台；浏览器始终只访问 Spring 同源 `/api`。
4. 录屏只包含浏览器产品页面和终端最终摘要，不录制 `.env`、容器环境、请求头、数据库控制台或真实模型密钥。

## 3–5 分钟讲解顺序

1. **0:00–0:40**：客户提交 80 小时物流延迟工单，说明 React 先读 Spring 权威快照，再消费同一授权视图的 SSE。
2. **0:40–1:30**：真实本地 Agent Server/LangGraph 使用固定假模型与受限 Spring 工具完成调查；Spring 独立复核出 `26.80 CNY` 模拟部分退款，客户只看到“等待人工审批”。
3. **1:30–2:20**：审批人领取 15 分钟租约，查看提案版本最小证据并批准；强调审批不等于执行，旧审批视图立即失权。
4. **2:20–3:30**：模拟执行器已记录退款但首次响应丢失，Spring 进入 `UNKNOWN`，客户看到“自动确认中”；普通重试被禁止，执行器以同一执行身份对账。
5. **3:30–4:20**：对账发现同一退款，客户只看到一条 `26.80 CNY`、尾号 `4242` 的成功结果，工单进入 `RESOLVED`；回读数据库验收断言只有一笔执行、一笔 provider operation 和一笔退款。
6. **4:20–5:00**：说明边界：这是可运行的本地全栈 Agent MVP；未验证真实支付、生产高可用、水平扩展、灾难恢复或强制进程重启后的 checkpoint 生存。

## 录屏后备检查表

- 目标文件名：`customer-agent-issue29-local-mvp.mp4`，建议 1080p、5 分钟以内。
- 开头显示仓库提交号与合成数据声明；结尾显示 smoke 成功摘要与上述边界。
