## 已定位的评测错误

1. **时长假设不匹配。** `agent/src/baseline_agent/graph.py:1585` 与行动模型旧兼容路径都要求精确整小时。Spring 补偿规则使用秒，但当前 Agent 入口并不支持初稿的非整小时组合。修正版按现有合同使用23/73小时，不擅自修改产品要求。
2. **审计断言错误。** `JdbcAgentInvestigationService.java:824` 后的提案路径写 `COMPENSATION_PROPOSAL_REVISION_CREATED/REUSED`，并持久化 `SUBMIT_INVESTIGATION_CONCLUSION` 的 `accepted=true`。普通回复的审计事件不能套到提案路径。对首轮两例的[离线证据复核](recheck.json)确认金额、状态、命令接受和唯一提案正确；原始 FAIL 不改写。截图已人工核对正文可见；两例刷新恢复在原脚本提前失败后未执行。
3. **受理输入歧义。** `deepseek_intake_model.py:148` 明确 `PACKAGE_NOT_RECEIVED` 更具体。初稿输入“物流延迟一直没收到”不足以保证只归为物流延迟。修正版明确描述物流轨迹更新延迟，去掉未收到表达。
4. **计量采集配置错误。** 本次生成 runner 时错误地将前端源码挂载加入 core-metrics，遮蔽其 Python 包，导致 `ModuleNotFoundError`。这是本次采集脚本问题。独立 `metrics.json` 未生成，`metricsCollected=false`，不能把事后预算汇总伪装成完整采集成功。持久账本和8例浏览器附件完整保留；受理调用按单worker用例时间窗口关联，其他调用按工单ID关联。
