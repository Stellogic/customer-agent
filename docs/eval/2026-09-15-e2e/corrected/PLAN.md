# 修正版端到端评测计划

这是首轮评测设计错误的纠正轮，不覆盖首轮结果，也不修改产品实现。

## 精确改动

1. 23小时59分59秒、72小时加1秒改为23小时、73小时。当前 Graph 明确要求 `delaySeconds == delayHours * 3600`，初稿错误地假定小时可向下取整。
2. 保持24小时、72小时档位样本；将通用的 `AGENT_CONCLUSION_ACCEPTED` 审计判断改为同代次 `SUBMIT_INVESTIGATION_CONCLUSION` 命令的 `accepted=true`。原两例提案实际上已经正确创建，但该路径使用提案审计事件。
3. 双问题描述改为“订单配送已经超过预计送达时间，物流轨迹更新延迟，另外我看到两笔扣款，请分别核查物流延迟和重复扣款。”避免“没收到”触发既有 `PACKAGE_NOT_RECEIVED` 优先分类规则。
4. frontend/src 挂载仅存在于浏览器服务；core-metrics 保持原 Python 包路径。付费调用之前增加一次无网络模块导入检查。
5. 允许仓库存在未跟踪评测文档，但受测已跟踪源码仍必须干净。产品提交不变，首轮与本轮脚本/计划分别冻结。
