# rag-layered-v2：检索与回答分层验收

2026-08-31，用户在 #190 的 grill-with-docs 对齐后明确批准，并授权同步所有受影响的正式 spec / tickets。正式依据为 [#149](https://github.com/Stellogic/customer-agent/issues/149) 及其修订票据。本文件是新协议，不改写 [rag-eval-v1](rag-eval-v1.md) 或原始结果；目前仅完成规格定义，不代表任一层已通过新验收。

## 产品职责

本地固定 BGE、中文全文检索、pgvector 与 RRF 返回授权 Top-5。权限、发布状态、版本和适用范围仍在排名前过滤；分数只决定排序，不判断能否回答。无匹配是正常空结果；无权限、索引过期、模型/数据库失败是明确的拒绝或故障，不能伪装成空结果。

客户回答及客服知识草稿复用各自负责生成回答的同一次 DeepSeek 调用，输入问题和授权相关片段，由它判断充分性并生成回答或说明不足。没有独立充分性调用，没有新增问答搜索入口。相关不等于充分；合法引文也不等于结论有依据。知识只能解释一般规则，个案事实、资格、金额和副作用仍受 Spring 权威约束。

仅因资料不足可以说明或追问，不自动转人工；模型/工具/检索故障及不安全回复沿用原有限重试、受控修正、停止和转人工规则。HUMAN 辅助失败不切换模式、不阻止人工继续处理。允许合成问题、工单、示例知识外发，不使用真实客户隐私或企业机密，不新建审批/分类/脱敏系统。新回答合同取消单条摘录 24 字符限制，保留来源授权、逐字引文真实性及在实际回复接缝固定的合理总输出上限；旧实验合同保持原样。

## 检索层：#190，消融由 #168 承接

使用 #189 原始冻结资产、标签、模型协议与哈希，完整执行全部样本，不挑选子集。报告协议名 `rag-layered-v2-retrieval`，保留实际有序候选、授权拒绝/故障状态以及 SHA/base、RunId、环境、模型 revision、数据哈希、耗时等证据。

| 必须通过的指标 | 门槛 |
| --- | --- |
| 有答案 Recall@5 | >= 0.90 |
| 有答案 MRR@5 | >= 0.75 |
| 错误版本、不适用范围、越权条目 Top-5 命中率 | 各为 0% |

召回、排名、禁止命中的计数含义与旧协议保持一致。无答案样本仍检索并记录，允许返回合法但不足以回答的片段；检索报告不计算语义拒答 precision/recall，不把缺失指标填成 PASS。无权限样本预期的权限拒绝是硬过滤证据；非预期服务错误不能算正确拒答或正常空列表。错误必须独立记录，不能通过丢弃错误样本取得完整通过结论。

本层达标且完成真实 PostgreSQL/浏览器验证、双轴审查和最终完整工程门禁，合入关票后可交付 #190。不等待回答层；新检索 PASS 不等价于旧 rag-eval-v1 全门 PASS，也不证明整个 RAG 问答可用。

## 回答层：#169 / #170

对应产品回答路径承接原无答案拒答 precision >= 0.90、recall >= 0.85 数值目标，协议名 `rag-layered-v2-answer`。复用冻结问题/标签，不以已见错题调 prompt 或选参；执行前固定实际产品 prompt/schema、模型配置、输出上限、样本映射、调用/尝试次数和累计预算。预算仍沿用既有账本，不能因新协议重置。不得调用独立判断实验并将结果冒充产品回答证据。

- 预测拒答只来自成功完成的实际回答：合法地明确资料不足，且未同时编造答案。检索空列表、模型分数、网络错误、权限拒绝、格式错误都不直接等于预测拒答。
- 无答案标签与分组保持原数据定义。precision 是正确拒答数 / 预测拒答数，recall 是正确拒答数 / 应拒答样本数；分母为零不视为通过。权限边界样本单独证明没有越权，不应为计算质量指标绕过授权给模型发材料。
- 结构合法性、引用真实性、语义充分性分列计数。结构不合法导致语义无法评估时标为未评估，不能命名为语义错误，也不能删样本后称整体 PASS；供应商/预算/未知 usage 等中止保留完整已运行数量、未运行数量和失败证据。
- 确定性测试验证接口与流程，真实 DeepSeek 运行验证实际语义能力。#169/#170 各自交付对应路径的回答证据；共享代码只在适用范围一致且明确标注时复用证据，不以客户结果自动证明客服投影，或反之。
- #173 汇总确定性真实全栈场景，#174 汇总真实产品发布验证；二者不反向成为 #169/#170 的前置，不重复实现产品判断模块。
